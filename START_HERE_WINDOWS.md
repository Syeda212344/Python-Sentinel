# START HERE — Python Sentinel (Django version) on your Windows laptop

## BEFORE YOU BEGIN

**This is a localhost capstone/demo app, not a production security product.** It stores data on your laptop and **generates clearly marked simulated incidents** for the final presentation. Do not present simulations as actual campus/laptop attacks. Real Windows monitoring is optional, limited to supported logs, and may be blocked by your university-managed laptop.

### 1. Install the software

1. **Python 3.11–3.13, 64-bit** — https://www.python.org/downloads/windows/
2. **Visual Studio Code** — https://code.visualstudio.com/download
3. In VS Code, install the official **Python** extension (Microsoft).
4. Chrome or Microsoft Edge. SQLite is built into Python; no MySQL server, Node, or React required.
5. **Internet access for first-time pip install**. Django 5.2 is installed through `requirements.txt`.

If your campus laptop blocks software installation, ask campus IT for approval or use a personal Windows laptop. Do not bypass security settings.

### 2. Unzip and open the correct folder

Right-click the `Python_Sentinel_Django.zip` file -> **Extract All**.
Then open **VS Code -> File -> Open Folder** and choose `Python_Sentinel_Django`, the folder containing `manage.py`.

### 3. Open a terminal in VS Code

Choose **Terminal -> New Terminal** and run:

```powershell
py --version
py -m pip install -r requirements.txt
```

Django + pywin32 (on Windows) will download. On Windows, you may instead run the helper `START_DEMO.bat` after Python is installed.

### 4. Set up the database

```powershell
py manage.py migrate
py manage.py seed_demo
```

`migrate` creates the three SRS tables and Django's migration bookkeeping table.
`seed_demo` creates **fictional events with timestamps spread over the past 75 days**. It is safe to rerun: it does not insert duplicates. If you need to rebuild only historical fake records for today's date, use `py manage.py seed_demo --reset` (do not use this casually if you want to retain edited sample statuses).

### 5. Launch the Django app on localhost

In PowerShell:

```powershell
$env:SENTINEL_MODE="demo"
py manage.py runserver 127.0.0.1:8000 --noreload
```

Now open: **http://127.0.0.1:8000/**

The first screen is an animated glowing PS shield. After about 2 seconds, the dashboard appears. The blue toggle on the top-right switches dark/light themes. The setting is remembered in your browser.

**Leave the terminal open.** Press `Ctrl+C` to stop the server.

### 6. Confirm that the backend works

1. Dashboard: shows records loaded for the past 75 days.
2. Click **Start Monitoring**.
3. Click **Normal Login**: stored event, no new alert.
4. Click **Failed Login**: an alert is generated by the enabled failed-login rule.
5. Click **Suspicious Process**, **Privilege Change** or **Service Stopped**: new alert for each matched rule.
6. Open **Alerts** -> **View details** -> confirm linked event, matched rule, severity, time and status. Click **Mark Reviewed**.
7. Go to **Detection Rules**. Disable Failed Login Detection, return to Dashboard, click Failed Login again: no *new* alert. Re-enable it.
8. Go to **Detection History** -> **Last 30 Days** -> **Apply Filter**. Repeat with **Last 2 Days** and **Last 2 Months**.
9. For any past date, use **Dashboard -> Simulate a Specific Date**, choose a calendar date, click **Generate 3 Events on This Date**. The app opens Detection History filtered to that exact date.
10. Switch between dark and light mode at any time.

### 7. Run white-box and API tests

Open a second VS Code terminal with the same project folder:

```powershell
py manage.py test sentinel.tests -v 2
```

Record the actual result for your final report. Tests cover event validation, rule branches, alert FK links, date ranges, toggles, API responses, and CSRF.

### 8. Optional: supported LIVE Windows event monitoring

**Only with university IT permission where necessary.** On a campus-managed laptop you may not have permission to read Security logs.

Stop the demo server, then:

```powershell
$env:SENTINEL_MODE="windows"
py manage.py runserver 127.0.0.1:8000 --noreload
```

Click Start Monitoring. The collector attempts to read supported Security/System/Application Windows Event Logs; its native mapping includes Windows 4625 (failed login) and 4624 (normal login). Other example scenarios are *simulated* and are **not** claimed to be live detection integrations. Demo buttons are disabled in Windows mode, and any seeded historical entries remain clearly marked SIMULATED.

### Troubleshooting

- **`'py' is not recognized`**: Python launcher wasn't installed; try `python --version` and use `python` instead of `py` throughout.
- **`No module named django`**: run `py -m pip install -r requirements.txt` in this project's terminal. Internet access is required for initial installation.
- **`no such table`**: run `py manage.py migrate`.
- **Port already in use**: run `py manage.py runserver 127.0.0.1:8001 --noreload` and open port 8001 in the browser.
- **Blank page / JavaScript error**: press Ctrl+Shift+R, check VS Code Terminal and browser DevTools Console (F12).
- **403 CSRF**: open the website using the same localhost address throughout, refresh the browser, and retry.
- **Windows access denied**: remain in demo mode. Do not override campus policies.
- **No records for an arbitrary date**: generate sample events using the specific-date simulator. Dates in the future aren't allowed.

### How the project is organized

| Location | Purpose |
|---|---|
| `sentinel/templates/sentinel/index.html` | Intro, PS branding, navigation and theme toggle |
| `sentinel/static/sentinel/style.css` | Cybersecurity warm-blue/light/dark design and transitions |
| `sentinel/static/sentinel/ps-shield.svg` | Vector 3D-effect PS shield logo |
| `sentinel/static/sentinel/app.js` | Browser frontend, buttons, AJAX, chart, date filters |
| `sentinel_site/urls.py` | Django routes / API URLs |
| `sentinel/views.py` | Request validation and API handlers |
| `sentinel/models.py` | SQLite-backed ORM tables: Events, Detection Rules, Alerts |
| `sentinel/services.py` | Event validation, rule matching, linked alerts, fake historical data |
| `sentinel/windows_events.py` | Optional Windows Event Log reader using pywin32 |
| `sentinel/monitoring.py` | Monitoring start/stop and background log polling |
| `sentinel/tests/test_app.py` | Unit / integration tests |

**The earlier plain-Python server is no longer used for this Django version.** Always run `manage.py`, not `app.py`.
